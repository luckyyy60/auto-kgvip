# KGVIP 自动签到

> 部署在 **Cloudflare Workers** 上的多账号自动签到服务：图形化控制台 · 扫码 / 手机验证码登录 ·
> 酷狗接口的签名与加密（MD5、AES-CBC、RSA、设备指纹）全部用纯 JS 在 Worker 内实现，
> 不依赖任何 Node 运行时与第三方 npm 运行时依赖。

![控制台首页](screenshots/02-dashboard.png)

> ⚠️ 本项目仅供学习与技术研究使用，请勿用于商业用途。音乐平台不易，请支持正版。

## 🚀 部署步骤

### 0. 前置条件

- 一个 Cloudflare 账号（免费版即可，无需绑卡）
- 本机 Node.js **22+**（Wrangler 4 要求 `node >= 22`）

```bash
git clone https://github.com/luckyyy60/auto-kgvip kg-qiandao-worker
cd kg-qiandao-worker
npm install
```

### 1. 创建 KV 命名空间

```bash
npx wrangler kv namespace create KG_KV
```

命令会输出一段配置，把其中的 `id` 复制到 `wrangler.toml`：

```toml
[[kv_namespaces]]
binding = "KG_KV"
id = "这里替换成上一步输出的 id"
```

> `wrangler.toml` 中预置的是占位 id，**必须替换成你自己账号下的 id**，否则部署会报找不到命名空间。
> 绑定名要保持 `KG_KV`（区分大小写），写错会提示未绑定。

### 2. 配置管理口令（必须）

控制台和全部接口都需要 `ADMIN_TOKEN`，未配置时接口会直接返回 403：

```bash
npx wrangler secret put ADMIN_TOKEN     # 输入一个足够复杂的管理口令
npx wrangler secret put SECRET_KEY      # 可选：用于加密 KV 里的 token，建议配置
```

> `SECRET_KEY` 一旦设置就不要再修改，否则已保存的 token 无法解密（此时页面会提示 token 失效，需要重新登录）。

### 3. 部署

```bash
npx wrangler deploy
```

部署成功后会输出形如 `https://kg-qiandao-worker.<你的子域>.workers.dev` 的地址，浏览器打开即可。

定时触发器已经在 `wrangler.toml` 中声明，部署后自动生效：

```toml
[triggers]
crons = ["*/5 * * * *"]
```

> `workers.dev` 域名在国内常被 DNS 污染，打不开的话可以用代理访问，或在 Cloudflare 给 Worker 绑定
> 自定义域名（**Worker → 设置 → 域和路由 → 添加自定义域**）。

### 4. 开始使用

1. 打开 Worker 地址，输入上一步设置的 `ADMIN_TOKEN` 进入控制台。
2. 点击「添加账号」，任选一种方式：
   - **扫码登录（推荐）**：点击「获取登录二维码」，用手机酷狗概念版 App 扫码并在手机上确认。
   - **手机验证码**：输入手机号 → 获取验证码 → 填验证码 → 登录。
   - **Cookie 导入**：填入已有的 `userid` 与 `token`。
3. 在账号列表里调整每日签到时间（北京时间），到点后 Worker 会自动执行。
4. 想立刻验证效果，点该账号的「执行」按钮，约 1~4 分钟后刷新查看结果。

## 🧭 控制台说明

- **首页说明**：账号列表上方固定展示两块说明，避免反复踩坑：
  - **新账号 / 老账号**：老账号拥有「看广告领 VIP」活动，除听歌外每天还能靠广告额外领取；新账号没有该活动（广告接口返回 `20028`），每天只能靠听歌领取。系统按接口实际返回自动判定，并在账号名旁标记 `老账号` / `新账号` / `类型未知`，无需手动设置。
  - **一个手机号绑定多个账号无法登录**：酷狗官方限制（错误码 `34175`），这种情况请改用扫码登录。
  - **酷狗概念版客户端**：桌面版推荐 [EchoMusic](https://github.com/hoowhoami/EchoMusic)，手机版推荐 2.4.5 版本。
- **账号列表**：账号名 + 类型标记 + 登录来源、UID / VIP 到期时间、签到时间（修改后点「确认」保存，不会自动提交）、状态、最近执行结果、启用开关。
  - `执行`：立即执行一次领取流程，**页面会等待并直接显示本次结果**（受时间预算约束，约 45 秒内返回）。
    广告若未领完，账号会标记 `待续跑`，剩余次数由后续定时任务自动继续，无需人工干预。
  - `日志`：展开该账号最近一次的分步执行明细。
  - `续期`：手动刷新 token。
  - `删除`：移除账号。
- **运行日志**：最近 100 条执行记录（定时 / 手动 / 续期），含每一步的成功与失败原因。
- **加载反馈**：登录校验、发送验证码、登录、执行、续期、清空日志、二维码获取与等待扫码等操作都会显示转圈动画。
- **时间修改**：账号列表和全局设置里的签到时间都不会自动保存 —— 改动后「确认」按钮才会变成**绿色**可点，点击才提交（输入框内按回车等效）。
- **登录页**：白色 K logo + 「酷狗概念版自动签到」，与 404 页同一套卡片视觉；点「退出」会清除本机口令并回到登录页。
- **设置**：

  | 设置项 | 默认 | 说明 |
  | --- | --- | --- |
  | 新账号默认签到时间 | `01:15` | 北京时间，24 小时制；修改后点「确认」保存 |
  | 每日广告领取次数 | `8` | 对应酷狗「看广告领 VIP」上限，`0` 表示只做听歌领取 |
  | 广告领取间隔 | `30` 秒 | 每次广告领取之间的等待时间，调小可加快执行 |
  | 每周日自动刷新 token | 开 | 与参考项目行为一致 |
  | 错过时间自动补签 | 关 | 开启后，当天错过签到时间的账号会在下次 Cron 时补跑（每天最多 3 次） |
  | 执行前设备注册获取 dfid | 关 | 更接近真实客户端，但与参考项目默认行为不同，可能引入额外失败点 |

> 为什么一次执行不把 8 次广告全领完？因为 8 次 × 30 秒间隔 ≈ 3.5 分钟，远超 HTTP 请求与
> `ctx.waitUntil` 的后台存活时限；强行一次跑完会被平台中断，账号就会永远停在「执行中」。
> 现在单次执行有时限，领不完的部分由每 5 分钟一次的定时任务自动续跑，直到领满或返回「次数已用尽」。

### 定时任务怎么工作

- Cron 每 5 分钟触发一次，判断「谁到了签到时间且当天还没执行过」，签到时间允许 ±5 分钟误差。
- 单次执行有时间上限（定时 2 分钟 / 手动 45 秒），8 次广告会被拆成多次执行自动续跑。
- 同一天最多自动重试 3 次，另有每天执行总次数上限兜底防止无休止重试。
- 开启「错过签到时间后自动补签」后，过了签到时间的账号会在后续 Cron 补跑。
- 每周日刷新 token 只执行一次（用 `lastRefreshDate` 去重），不会每个 Cron 周期重复刷新。

除 `GET /api/status` 外，所有接口都需要携带管理口令，支持三种方式：
`Authorization: Bearer <token>`、`X-Admin-Token: <token>`、`?token=<token>`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 控制台页面 |

| POST | `/api/accounts` | 新增/更新账号（Cookie 导入，导入时校验 token） |

| DELETE | `/api/accounts/:id` | 删除账号 |
| POST | `/api/accounts/:id/run` | 立即执行该账号 |
| POST | `/api/accounts/:id/refresh-token` | 手动刷新 token |
| POST | `/api/accounts/run-all` | 执行全部启用账号 |
| POST | `/api/auth/sms/send` | 发送手机验证码 |
| POST | `/api/auth/sms/login` | 手机验证码登录并加入托管 |
| GET | `/api/auth/qr/create` | 获取登录二维码 |
| GET | `/api/auth/qr/check?key=` | 轮询二维码状态（`4` = 登录成功） |
| GET/POST | `/api/settings` | 读取 / 更新全局设置 |
| GET/DELETE | `/api/logs` | 读取 / 清空日志 |
| POST | `/api/refresh-tokens` | 刷新全部账号 token |
| POST | `/api/run-scheduled` | 手动触发一次定时检查（调试用） |

## ❓ 常见问题

**Q：手机验证码登录提示「该手机号绑定了多个账号」？**
酷狗官方限制（错误码 `34175`），一个手机号绑定多个账号时无法用验证码登录，请改用**扫码登录**。

**Q：扫码后一直显示「等待扫码」？**
二维码有效期只有几分钟，超时后页面会提示「二维码已过期」，点「刷新二维码」重新获取即可；
另外必须用手机酷狗概念版 App 扫码，并在手机上点击确认。

**Q：账号显示「登录失效」？**
token 过期或被顶号。重新扫码/验证码登录即可（同一账号会自动覆盖更新，不会重复添加）。

**Q：`wrangler` 报 `auth token has expired and could not be refreshed`？**
OAuth 凭证过期，非交互环境无法自行刷新。在**交互式终端**重新执行 `npx wrangler login` 即可。

**Q：定时任务没有执行？**
1. 确认账号处于「启用」状态；
2. 签到时间使用**北京时间**，Cron 每 5 分钟匹配一次，允许 ±5 分钟误差；
3. 当天已执行过（包含手动执行）的账号不会重复执行；
4. 可在「运行日志」查看是否有对应记录，或调用 `POST /api/run-scheduled` 手动触发排查；
5. 想更宽松可在设置里开启「错过签到时间后自动补签」。

**Q：广告领取显示「今日次数已用尽」？**
属于正常情况，说明当天 VIP 已领满。

**Q：广告领取显示「该账号无广告领取活动（新账号）」，是出错了吗？**
不是。这是**账号本身的差异**：酷狗的这个「看广告领 VIP」活动只对老账号开放，新账号调用广告接口会返回
`20028`。系统把它识别为账号属性而非执行失败，并自动把该账号标记为 `新账号`（账号名旁可见）。这类账号
每天只能靠听歌领取，属于平台规则，无法绕过。
对照：老账号调用同一接口会返回 `30002`（今日次数已用尽）或直接领取成功，两种都会被标记为 `老账号`。

**Q：能不能把新账号「升级」成老账号？**
这由酷狗的活动资格决定，本项目无法也不应绕过。可以在酷狗 App 的「活动中心 → 天天签到领 VIP」确认该账号
是否有此活动入口。

**Q：点了「执行」，状态显示「待续跑」是什么意思？**
说明本次时间预算内没能把广告次数全部领完，剩余次数会在下一次定时任务（每 5 分钟）自动继续，
不需要你再点一次。这是为了避免长时间执行被平台中断导致状态卡死，属于正常行为。

**Q：听歌领取失败，提示 `error_code=30002 GET LOCK FIAL` 是什么意思？**
这是酷狗的**并发锁竞争**错误（`FIAL` 是酷狗原文拼写错误，实为 `FAIL`）：服务端没能拿到该账号的操作锁，
说明**同一个账号在同一时刻被发起了多次领取请求**。常见原因：

- 手动点了「执行」，同时定时任务也在跑这个账号；
- 在手机 App 上和其他设备同时领取；
- 上一次执行还没结束就又点了一次。

本项目已做三层处理：① 同一账号禁止并发执行（正在执行时会直接跳过并提示）；② 听歌遇到锁竞争会
等待 3 秒自动重试一次；③ 仍然失败则标记 `待重试`，由定时任务在当天继续重试（最多 3 次）。
**遇到这个提示不需要手动做什么**，稍等几分钟会自动恢复。

> 注意：`30002` 是通用错误码，含义随接口不同——在**广告**接口上表示「今日次数已用尽」（正常终态），
> 在**听歌**接口上表示「获取锁失败」（临时错误）。本项目按错误文案区分处理，不会把锁冲突误判成领满。

**Q：账号一直显示「执行中」不动？**
正常执行最多持续约 2 分钟（定时任务）或 45 秒（手动执行）。若超过 3 分钟仍显示「执行中」，
说明上一次执行被平台中断，界面会自动把它纠正为「失败」并提示，随后定时任务会重新执行，无需手动处理。

**Q：为什么默认关闭「设备注册获取 dfid」？**
参考项目签到流程中 dfid 取值为 `-` 且工作正常，因此默认保持一致，减少一个可能失败的风控环节。

**Q：免费版 Worker 够用吗？**
够用。Cron 触发器免费版可用，KV 免费额度对个人多账号场景绰绰有余。

KV 免费额度是**读 10 万/天、写/删/列出各 1000/天**。本项目对「写」做了专门优化：

| 场景 | 旧实现 | 现在 |
| --- | --- | --- |
| 一次完整签到（11 个步骤） | 约 14 次写 | **3~5 次写**（running + 结果 + 日志，中间进度最多 2 次） |
| 周日自动刷新 token | 一整天每 5 分钟刷一次（约 288 次写） | **当天只刷 1 次** |
| 设备指纹读取（含二维码轮询） | 可能每次读都写回 | 只在缺字段时写一次 |

按 5 个账号估算：日常写操作约 **55 次/天**（占 5.5%）、读操作约 **650 次/天**（占 0.65%），
远低于上限；代码里也没有任何 `list` 调用。

> 注意：**Cloudflare 控制台和 wrangler 的操作同样计入额度**，KV 页面每次刷新/搜索都会产生 list 请求。
> 另外 Cron 每次空转只消耗 2 次读，不会产生写。

**Q：迁移/导入原有 KV 数据后，账号列表却是空的？**
先确认键名。正式键名是 `kg:accounts`（**冒号**），早期版本和「按导出文件名导入」的场景会写成
`kg_accounts`（下划线），两者不通用。检查命令：

```bash
npx wrangler kv key list --namespace-id <你的 KV id> --remote
```

若列出的是下划线键名，当前版本的代码会自动回退读取并迁移到正式键名，重新部署一次即可；
也可以手动把值复制到 `kg:accounts` / `kg:device` / `kg:settings` / `kg:logs`。

**Q：接口返回 403「服务端未配置 ADMIN_TOKEN」？**
说明没有执行 `npx wrangler secret put ADMIN_TOKEN`（`.dev.vars` 只在本地开发时生效，不会部署到线上）。
设置后需要 `npm run deploy` 重新部署一次。

**Q：部署后仍提示未绑定 KV？**
检查 `wrangler.toml` 里的绑定名是否**严格等于** `KG_KV`（区分大小写），改好后重新 `npm run deploy`。

**Q：`workers.dev` 地址打不开？**
`*.workers.dev` 在国内常被 DNS 污染。用代理访问，或在 Cloudflare 给 Worker 绑定自定义域名
（**Worker → 设置 → 域和路由 → 添加自定义域**）。

**Q：改了 KV 数据但页面还是旧的？**
KV 是**最终一致**的，边缘缓存最长约 60 秒。等一分钟再刷新，或重新部署一次。
